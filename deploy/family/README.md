# OpenTodo для семьи

Готовый набор для запуска своего OpenTodo для одной семьи: четыре участника и ИИ-агент-помощник в одном контейнере, на порту 4002. Файл `docker-compose.yml` сам собирает образ из этого репозитория, хранит все данные в томе `opentodo-data` (внутри контейнера — `/data`) и перезапускает сервер после сбоя и перезагрузки (`restart: unless-stopped`).

## Быстрый старт

Набор живёт в ветке `family-pack` вашего форка (база — upstream v1.5.0):

```bash
git clone https://github.com/<ваш-логин>/opentodo.git opentodo
cd opentodo
git switch family-pack
cd deploy/family
docker compose up -d --build
```

Сборка занимает несколько минут (в образ входит веб-приложение и сервер). Когда контейнер поднят, откройте <http://localhost:4002>.

Необязательные переменные окружения (адрес под доменом, пресеты ИИ-ассистента) живут в `.env.example`: скопируйте его в `.env` и раскомментируйте нужное — compose подхватит файл сам. Остальные переменные сервера — в [docs/self-hosting/docker.md](../self-hosting/docker.md).

Если сервер запускается на домашнем сервере или NAS, а открывать вы будете с другого устройства, при первом входе экран настройки попросит код установки: возьмите его из журнала контейнера — он печатается один раз, пока у сервера нет владельца:

```bash
docker compose logs opentodo
```

## Создайте аккаунт администратора

Первый, кто откроет <http://localhost:4002>, создаёт аккаунт владельца — это взрослый, который будет управлять сервером: приглашать родных, включать интеграции и настройки резервных копий. Регистрация для посторонних закрыта по умолчанию (`OPENTODO_ALLOW_SIGNUP` не включён), так что аккаунты создаются только по приглашениям.

## Пригласите четырёх участников семьи

В настройках откройте **Люди → Пользователи и приглашения** и создайте одноразовые ссылки-приглашения для каждого из четырёх членов семьи (по умолчанию — родитель, второй взрослый и двое детей). Передайте каждому ссылку по своему каналу: открыв её, человек создаёт свой аккаунт и попадает в семью. Не включайте открытую регистрацию: она доступна всем, кто может достучаться до сервера.

Дальше создайте общий проект, например «Семья» или «Дом», и добавьте в него всех участников: участники общего проекта видят его задачи и могут получать задачи как исполнители.

## Переключите интерфейс на русский

Каждый участник делает это в своём аккаунте: **Настройки → Язык и регион → Язык → «Русский»**. Интерфейс, даты и уведомления подхватят выбор.

## Включите тему «Sunny Family»

Для детей подойдёт светлая тема **Sunny Family** — яркая, весёлая и контрастная: кремовый фон, солнечно-жёлтый акцент и коралловый вторичный цвет. Выберите её в **Настройки → Оформление**.

## Поставьте приложение на телефон

- **Android:** установите APK — см. [docs/android-app.md](../../docs/android-app.md).
- **iPhone, iPad и Android (PWA):** откройте сервер в браузере и добавьте его на домашний экран — см. [docs/install-app.md](../../docs/install-app.md).

Пуш-уведомления и работа офлайн требуют HTTPS или `localhost`; на простом адресе локальной сети (`http://192.168.x.x:4002`) всё остальное работает, но для пушей поставьте сервер за обратным прокси с сертификатом (см. [docs/self-hosting/docker.md](../self-hosting/docker.md)).

## Подключите ИИ-агента

Набор настроен на то, чтобы помощник работал сразу: переменная `OPENTODO_MCP` включает MCP-эндпоинт с первого старта. Дальше по шагам — создание agent-токена, конфигурация opencode, роль агента, бэклог агентских задач и исполнители — в русском руководстве [docs/agents-ru/AGENTS.md](../../docs/agents-ru/AGENTS.md); готовый пример конфигурации — [docs/agents-ru/opencode.json](../../docs/agents-ru/opencode.json).

Два переключателя остаются за людьми: владелец разрешает изменения ассистентам (**Настройки → Интеграции → AI-ассистенты → Ассистенты могут вносить изменения**), и каждый участник включает это для своего аккаунта. Каждое изменение агента видно в истории задачи и в журнале аудита, и его можно отменить.

## Настройте резервные копии

Владелец настраивает их в **Настройки → Сервер → Резервные копии**: расписание, сколько копий хранить, шифрование и место (папка на сервере, S3 или WebDAV). Полное руководство — [docs/backups.md](../../docs/backups.md). Простейший вариант — папка на сервере, она лежит внутри того же тома `opentodo-data`; для защиты от потери диска выберите S3 или WebDAV.

## Обновление

```bash
cd opentodo
git switch family-pack
git pull                        # из вашего форка
cd deploy/family
docker compose up -d --build
```

Данные живут в томе `opentodo-data` и переживают пересборку контейнера. Перед обновлением сделайте резервную копию.
